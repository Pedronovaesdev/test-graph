## 3.3 Fluxo de dados e lógica do sistema

O `test-graph-selector` é uma ferramenta de linha de comando (não uma aplicação web), tipicamente disparada em CI a cada Pull Request. Dado um diff de Git, ela constrói um grafo de dependências a partir do código-fonte real (AST) e seleciona apenas os testes afetados pela mudança. É determinística e não usa IA no núcleo.

### 3.3.1 Entrada de dados

A entrada não é um payload HTTP, mas argumentos de linha de comando: dois refs de Git (`base_ref`, `head_ref`) e o diretório do projeto alvo. O script executa:

```
git diff --name-only "$BASE_REF" "$HEAD_REF" -- '*.java'
```

O resultado é uma lista de **caminhos de arquivo** alterados (granularidade de arquivo, não de linha), gravada em um arquivo temporário. Não há entrada de rede, config remota ou credenciais.

### 3.3.2 Processamento clássico

Processamento 100% determinístico, em duas fases:

**a) Construção do grafo** (específica por linguagem):

| Linguagem | Técnica | Granularidade |
|---|---|---|
| Java | JavaParser + Symbol Solver (resolução real de tipos) | método/classe (call graph) |
| Python | módulo `ast` da stdlib | arquivo (grafo de imports) |
| Node (TS/JS) | `ts-morph` (compilador TS) | arquivo (grafo de imports) |

Python e Node produzem um JSON intermediário (contrato em `docs/graph-schema.md`), lido pelo motor Java via `--graph-json`. Java é indexado direto em memória via `--src`.

**b) Consulta ao grafo** (motor único, agnóstico de linguagem):
- `DependencyGraph.ancestorsOf(nó)` — BFS sobre o grafo invertido, encontra tudo que depende (direta ou indiretamente) do nó alterado.
- `TestSelector` — filtra, entre esses dependentes, quais são nós marcados como teste.

### 3.3.3 Integração com serviços de IA

**Não aplicável.** Nenhum LLM, embedding ou classificador é usado. Decisão de projeto explícita: seleção de testes em CI precisa ser auditável e reprodutível, e um componente probabilístico introduziria a variância que a ferramenta existe para eliminar. Confirmado pelas dependências do `pom.xml` (JavaParser, JGraphT, Jackson, picocli — nenhuma lib de IA/ML).

### 3.3.4 Indexação e recuperação de dados para IA

**Não aplicável** (não há RAG, embeddings ou busca vetorial). O paralelo estrutural que existe: o "índice" é o grafo de dependências reconstruído a cada execução, a "chave" é o id do nó (FQCN em Java ou caminho relativo em Python/Node), e a "recuperação" é uma travessia exata de grafo (BFS), não uma busca por similaridade.

### 3.3.5 Persistência

Sistema sem estado entre execuções: não há banco de dados nem cache. Os únicos artefatos em disco são efêmeros (arquivos temporários criados via `mktemp` e apagados ao final do script): a lista de arquivos alterados e o grafo JSON (Python/Node). O grafo Java em memória nunca é serializado. Limitação conhecida: o grafo é reconstruído do zero a cada execução — cachear entre execuções de CI é um próximo passo natural, ainda não implementado.

### 3.3.6 Retorno da execução

Sem frontend web — o retorno acontece em duas camadas:

1. **Motor → script**: saída via stdout, em formato `human` (legível, com justificativa) ou `csv` (lista de testes, consumida pelo script).
2. **Script → executor de testes**: a lista selecionada é injetada no comando nativo (`mvn -Dtest=...`, `gradle --tests ...`, `pytest <arquivos>`, `jest <arquivos>`). O código de saída desse executor é o que efetivamente determina o resultado do job de CI.

### 3.3.7 Exemplo de fluxo completo (Java)

Alteração em `Calculator.java`:

1. `git diff --name-only` retorna `src/main/java/com/example/Calculator.java`.
2. `AstIndexer` indexa todo o projeto e monta o grafo completo (nós: `Calculator`, `CalculatorTest`, `Logger`, `LoggerTest`; aresta `CalculatorTest → Calculator`).
3. O caminho alterado é traduzido para o FQCN `com.example.Calculator`.
4. `TestSelector` chama `ancestorsOf("com.example.Calculator")` → encontra `CalculatorTest` (que depende dele); `Logger`/`LoggerTest` ficam de fora por não terem aresta até `Calculator`.
5. Saída CSV: `com.example.CalculatorTest`.
6. Script executa `mvn -q test -Dtest=com.example.CalculatorTest` — apenas esse teste roda.

O mesmo roteiro se repete para Python (`calculator.py` → `test_calculator.py`) e Node (`logger.ts` → `logger.test.ts`), trocando apenas o extrator na etapa 2.
